# AGENTS.md

Rules for any agent (or human) working in this repository. 

## Repo layout

- Wails v2 app. Go backend in `app.go`/`main.go`; frontend in `frontend/` (React + TypeScript, built by vite).
- `frontend/wailsjs/**` and `frontend/package.json.md5` are generated by the Wails CLI and **untracked** (regenerated by any `wails` run). Nothing in `src/` imports them.
- `wails.json` carries `"build:tags": "webkit2_41"` — this machine targets webkit2gtk 4.1; do not remove it.

## Branches, commits, PRs

- Work branches are named `<ticket-number>-<short-slug>`, cut from a fresh fetch of `dev`.
- Conventional Commits, short subjects, no bodies, no Co-Authored-By or Generated-with trailers: `fix:`, `feat:`, `docs:`, `chore:`.
- PR titles follow `[<ticket-number>] <type>: <short message>`, e.g. `[1] feat: basic Tiptap editor`.
- PRs target `dev`; never push feature work to `dev` or `main` directly.

## Tickets

- Every unit of work gets a GitHub issue first; branch numbering comes from the issue number (issues and PRs share the number sequence — a new PR takes the next number, so check before assuming).

## Running locally

- Requirements: Go (per `go.mod`), Node/npm, and on Linux `libwebkit2gtk-4.1-dev` + `pkg-config`.
- Dev: `wails dev` (vite live reload). Release build: `wails build` (the `webkit2_41` tag comes from `wails.json`).
- Backend-only builds (`go build`/`go vet ./...`) fail on fresh checkouts until `frontend/dist` exists — `main.go` embeds it; run `npm run build` in `frontend/` once. CI handles this itself.
